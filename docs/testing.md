# 测试指南

测试分两部分：自动化测试 5 分钟跑完，验证核心逻辑没坏；手动测试大约 20 分钟，验证真实网站、真实 API Key 和 YouTube。发布前两部分都要过一遍。

---

## 一、自动化测试

**第一步，安装依赖（只需一次）。**

```bash
pip3 install playwright
python3 -m playwright install chromium
```

**第二步，在项目根目录运行。**

```bash
python3 tests/e2e.py            # 无头模式
python3 tests/e2e.py --headed   # 弹出浏览器窗口，可以看到每一步
```

**第三步，看结果。** 全部通过时输出 `结果：14/14 通过`，退出码为 0。截图保存在 `tests/output/`，可以打开检查双语排版、仅译文模式和划词面板。

覆盖范围：

| 分组 | 验证内容 |
| --- | --- |
| 翻译引擎 | Google 返回中文；未配置 Key 的引擎给出中文报错 |
| 整页翻译 | 单元数量正确；代码块、中文段落被跳过；导航链接逐个翻译 |
| 仅译文模式 | 原文被隐藏 |
| 划词翻译 | 选中出现图标，点击后面板显示译文 |
| 还原页面 | 译文和标记全部清除 |
| 大模型批量 | 用本地 mock 接口验证 11 段只发 1 次请求 |

测试需要能访问 Google 翻译。网络受限导致第 1、2 组失败时，先确认浏览器能打开 `translate.googleapis.com`。

### 更多测试脚本

| 脚本 | 用途 | 需要什么 | 用时 |
| --- | --- | --- | --- |
| `tests/e2e.py` | 核心逻辑回归（本地测试页 + mock 大模型） | 网络 | 约 1 分钟 |
| `tests/e2e_real.py` | 真实网站与交互：维基百科、Hacker News、MDN、悬停、输入框、面板、侧边抽屉与生词本、工具栏开关侧面板与本页生词、网站规则、导入、样式、右键菜单（46 项） | 网络 | 约 2 分钟 |
| `tests/e2e_account.py` | 账户与订阅：注册、登录、错误提示、令牌续期、升级、支付返回变 Pro、管理订阅（22 项） | 无（使用模拟的 Supabase 接口） | 约 30 秒 |
| `deno test … supabase/functions/` | 后端订阅逻辑与 Stripe 签名验证（9 项） | 已安装 Deno | 约 5 秒 |
| `tests/e2e_local_billing.py` | 真实联调：本地 Supabase + Stripe 测试 / 沙盒，注册、邮箱验证、付款、变为 Pro、到期取消（15 项） | 本地后端已启动（见 [本地运行指南](local-dev.md)） | 约 2 分钟 |
| `tests/e2e_engines.py` | 用你的 API Key 测试各引擎：测试连接、批量 8 段顺序、中译英、整页翻译 | `tests/.env.local` 中的 Key | 每个引擎约 10–30 秒 |
| `tests/e2e_youtube.py` | YouTube 真实字幕（会弹出浏览器窗口） | 网络 | 约 40 秒 |

`e2e_real.py` 支持 `--only wiki,hn` 只跑部分场景，`--headed` 显示浏览器窗口。

**测试引擎的步骤：**

```bash
cp tests/env.example tests/.env.local   # 该文件已被 git 忽略
# 编辑 tests/.env.local，只填你有的 Key
python3 tests/e2e_engines.py            # 未填 Key 的引擎自动跳过
python3 tests/e2e_engines.py --only deepl,claude
```

脚本不会打印 Key，结束时输出一张汇总表。

> **关于 YouTube：** 自动化浏览器会被 YouTube 识别，字幕接口返回空内容（连 YouTube 自己的原生字幕也不显示），因此 `e2e_youtube.py` 在部分网络环境下必然失败。这不代表扩展有问题，以你日常使用的 Chrome 手动验证为准（见下方清单第 9 项）。

## 二、手动测试

### 准备

**第一步，加载扩展。** 打开 `chrome://extensions` → 开启“开发者模式” → “加载已解压的扩展程序” → 选择项目根目录。

**第二步，固定图标。** 点击地址栏右侧的拼图图标，把“微光翻译”固定到工具栏。

**第三步，准备测试页。** 推荐以下几类网站，覆盖不同的页面结构：

| 类型 | 推荐网站 | 重点观察 |
| --- | --- | --- |
| 静态文章 | 维基百科英文版、BBC News | 段落、标题、列表、表格 |
| 动态加载 | Hacker News、Reddit、X（Twitter） | 滚动后新内容是否自动翻译 |
| 技术文档 | MDN、GitHub README | 代码块是否被正确跳过 |
| 视频 | YouTube 任意带字幕视频 | 双语字幕 |

### 测试清单

逐项操作，在方框里打勾。

**1. 整页翻译**

- [ ] 打开英文维基百科任意词条，点击右侧悬浮球，段落下方出现中文译文
- [ ] 悬浮球变为紫色渐变，左上角绿点亮起；翻译过程中绿点变黄闪烁
- [ ] 向下滚动，下方段落陆续翻译（不是一次性全部翻译）
- [ ] 再次点击悬浮球，所有译文消失，页面恢复原样
- [ ] 按 `Alt+A` 同样可以切换

**2. 显示模式与样式**

- [ ] 鼠标移到悬浮球上，点击“仅译文”，原文隐藏，段落间距正常
- [ ] 按 `Alt+S` 切回双语
- [ ] 面板 → 设置 → 译文样式，依次切换“高亮”“引用条”“学习模式”，已翻译的页面实时变化
- [ ] 学习模式下译文模糊，鼠标悬停时变清晰

**3. 动态内容**

- [ ] 在 Hacker News 或 Reddit 开启翻译，点击“More”或滚动加载更多，新内容自动翻译
- [ ] 在 X 上开启翻译，向下滚动时新推文被翻译

**4. 划词翻译**

- [ ] 选中一段英文，鼠标旁出现紫色图标，点击后弹出面板显示译文
- [ ] 选中一段中文，面板自动翻译成英文
- [ ] 面板中切换引擎下拉框，重新翻译
- [ ] 点击“🔊 译文”能朗读，“复制”后可粘贴
- [ ] 拖动面板标题栏可移动；按 `Esc` 或点击空白处关闭
- [ ] 右键选中文字 → “翻译‘…’”同样弹出面板

**5. 悬停翻译**

- [ ] 页面未开启整页翻译时，鼠标指向某段落，按一下 `Alt`，只有这一段被翻译
- [ ] 同一位置再按一次 `Alt`，这段译文消失

**6. 输入框翻译**

- [ ] 面板 → 设置 → 输入框翻译，选择 English
- [ ] 在任意搜索框输入“今天天气很好”，然后连按三次空格，内容被替换为英文

**7. 侧边面板**

- [ ] 点击工具栏图标，面板从网页右侧滑出，紧贴右边缘、占满全高；再点一次滑回收起；`Alt+Q` 效果相同
- [ ] 右侧图标栏悬停时显示文字提示，当前页面的图标高亮
- [ ] 网页上鼠标移到悬浮球，点击“面板”，同样滑出，悬浮球移到面板左侧
- [ ] 安装或重新加载扩展后，不刷新之前打开的网页，直接点击工具栏图标，面板仍能滑出
- [ ] 在面板首页打开“翻译此页面”，网页开始翻译；再点悬浮球关闭翻译，面板中的开关同步变为关闭
- [ ] 面板 → 设置 → 翻译语言选择“日本語”，返回后该行显示新值，网页译文变为日语
- [ ] 面板 → 设置 → 翻译引擎，未配置 Key 的引擎显示“需 API Key”，选择后提示需要配置
- [ ] 打开“总在此网站开启”，刷新页面后自动开始翻译
- [ ] 在快速翻译框输入文字并回车，下方显示译文
- [ ] 点击面板的 ✕ 或按 `Esc`，抽屉收起
- [ ] 在 `chrome://extensions` 页面、完整设置页、新标签页点击工具栏图标，都直接弹出面板（弹窗形态），并提示当前页面不支持网页翻译
- [ ] 完整设置页 → 高级 → “当前版本”的提交编号，与项目目录 `git log --oneline -1` 一致

**7.1 生词本**

- [ ] 选中一个英文单词，在划词面板点击“☆ 收藏”，变为“★ 已收藏”，页面顶部提示已收藏
- [ ] 面板首页生词本数字加 1，“本页生词”中出现该词；右侧栏生词本图标出现数字角标
- [ ] 打开另一个包含该词的网页，“本页生词”中出现它；打开不包含的网页，显示“本页没有生词本中的单词”
- [ ] 点击“展开释义”显示译文，再点收起；刷新后保持上次的选择
- [ ] 点击勾选框，单词变灰（已掌握）；生词本页显示“已掌握 1 / N”
- [ ] 点击红心，单词从本页生词和生词本中移除
- [ ] 在生词本中点击朗读，功能正常
- [ ] 再次选中同一个词，划词面板直接显示“★ 已收藏”，点击后取消收藏

**7.2 账户与订阅（需要先部署后端，见 [后端部署指南](backend.md)）**

- [ ] 面板 → 设置，第一行“账户”显示“登录 / 注册”
- [ ] 注册新邮箱，提示查收验证邮件；点击邮件链接后回到面板登录成功
- [ ] 输错密码提示“邮箱或密码错误”；输错后已填写的内容不会被清空
- [ ] 忘记密码：填写邮箱后点击，收到重置邮件
- [ ] 免费版点击“月付”，新标签页打开 Stripe 支付页；用测试卡 `4242 4242 4242 4242` 付款
- [ ] 支付后回到面板，几秒内变为“Pro 会员”并显示续费日期；首页标题栏出现金色 Pro
- [ ] “管理订阅”打开 Stripe 客户门户；取消订阅后显示“已取消续费，Pro 有效期至……”
- [ ] 退出登录后回到登录表单；关闭浏览器再打开，登录状态仍然保持

**8. 翻译引擎（需要你自己的 Key）**

在完整设置页“翻译服务”中逐个填入 Key 并点击“测试连接”，绿色 `✓` 加耗时加译文即为通过：

- [ ] DeepL
- [ ] OpenAI GPT
- [ ] Google Gemini
- [ ] DeepSeek
- [ ] Anthropic Claude
- [ ] Microsoft（Azure）
- [ ] 自定义（如本地 Ollama，记得设置 `OLLAMA_ORIGINS`）

每配置好一个，“设为默认”后在维基百科上做一次整页翻译，确认长页面也能正常完成。故意填一个错误 Key，确认报错信息可读（如“API Key 无效或未授权”）。

**9. YouTube 双语字幕**

> 自动化测试只验证了字幕解析和渲染，真实字幕的拦截需要在你自己的 Chrome 中验证，这一项最重要。

- [ ] 打开一个有英文字幕的视频（如 TED 演讲），点击播放器的 CC 按钮
- [ ] 原生字幕消失，出现上原文、下译文的双语字幕
- [ ] 自动生成字幕被合并成完整句子，不是零碎的单词
- [ ] 鼠标移到字幕上视频暂停，移开后继续播放
- [ ] 点击字幕中的单词弹出翻译面板
- [ ] 全屏后字幕仍然显示
- [ ] 点击推荐列表切换到另一个视频，旧字幕清空，打开 CC 后显示新视频的字幕
- [ ] 设置页关闭“YouTube 双语字幕”，恢复显示原生字幕

**10. 设置持久化**

- [ ] 修改若干设置后关闭浏览器再打开，设置保留
- [ ] 设置页 → 高级 → 导出设置，再修改设置，导入刚才的文件，设置恢复
- [ ] 导入 `docs/settings.example.json`，成功

## 三、发现问题时怎么排查

| 现象 | 去哪里看 |
| --- | --- |
| 翻译失败、报错 | `chrome://extensions` → 本扩展 → 点击“Service Worker”，在 DevTools 的 Network 中查看失败的请求和响应体 |
| 页面上没反应 | 网页 DevTools → Console，顶部上下文选择“微光翻译”，看是否有报错 |
| 某段排版错乱 | 网页 DevTools → Elements，找到对应的 `<gl-trans>` 元素和它的父元素 |
| 译文没有更新 | 可能命中了缓存，设置页 → 高级 → 清除缓存后重试 |

提交问题时请附上：网址、操作步骤、使用的引擎、Console 或 Network 中的报错截图。
